# Test Strategy

일반 경매와 Live 경매가 동일한 경매 정책을 지키면서 통합 환경에서 배포·시연 가능한지 검증한다.

## 테스트 수준

| 수준 | 책임 | 목적 | 실행 명령 |
| --- | --- | --- | --- |
| Frontend | `dib-frontend` | 일반 탐색, Live 피드와 판매자 제어 UI 검증 | TBD |
| Backend | `dib-backend` | API, 상태 전이, 동시성·인가 규칙 검증 | TBD |
| AI | `dib-ai` | 상품 심사와 이상 거래 탐지 결과 형식 검증 | TBD |
| Infrastructure | `dib-infra` | 데이터·메시징·송출 의존성과 배포 구성 검증 | TBD |
| Integration | `dib-orchestration` | 컴포넌트 간 핵심 사용자 흐름과 계약 검증 | TBD |

상세 테스트 구현과 명령은 각 컴포넌트가 소유한다. 이 문서는 시스템 전체 범위와 통합 합격 조건을 관리한다.

## 계약 테스트 기준

- REST 요청·응답과 오류가 Google Sheet의 API·오류 코드 계약에 맞는다.
- WebSocket 스냅샷·증분 이벤트·재연결 동기화가 같은 최종 상태를 만든다.
- Kafka producer와 consumer가 버전 스키마, `auctionId` 순서, 중복 이벤트를 처리한다.
- Redis 키/TTL과 스케줄 버전이 원본 Sheet에 맞고 캐시 유실 후 복구할 수 있다.
- 익명·회원·판매자 권한 매트릭스를 REST와 WebSocket 모두에서 검증한다.

## 필수 통합 시나리오

| 시나리오 | 기대 결과 | 상태 |
| --- | --- | --- |
| 익명 일반 경매 탐색 | 홈·목록·검색·상세와 마스킹 입찰 내역 조회 성공, 상태 변경 거절 | Not ready |
| 일반 경매 예약 생성 | AI 승인 및 소유권 확인 후 `SCHEDULED`, 시작·종료 작업 등록 | Not ready |
| 일반 경매 자동 시작·종료 | 예약 시각에 한 번만 시작하고 확정 종료 시각에 낙찰/유찰 처리 | Not ready |
| 시작 전 수정·취소 | `SCHEDULED`에서는 성공, `ACTIVE` 이후에는 지정 오류 | Not ready |
| 상품 중복 노출 경쟁 | 동시 요청에서도 예약/진행 일반과 진행 Live 중 하나만 성공 | Not ready |
| 첫 입찰과 예치금 | 10%, 최소 1,000원 예치 후 입찰 성공, 이후 추가 충전 없음 | Not ready |
| 입찰 동시성과 멱등성 | 최고 유효 입찰 하나만 반영하고 동일 `commandId`는 중복 생성 안 함 | Not ready |
| 마감 연장 | 마지막 30초의 유효 입찰마다 15초 연장, 오래된 종료 작업 무시 | Not ready |
| 익명 Live 시청 | 영상·현재 상품/경매 상태·시청자 수만 수신, 채팅·상세·입찰·신고 거절 | Not ready |
| Live 준비와 시작 | 최대 10개 승인 상품 설정 후 즉시 방송 시작, 방송 중 피드에 노출 | Not ready |
| Live 단일 활성 경매 | 판매자 수동 시작 성공, 두 번째 동시 시작 거절 | Not ready |
| Live 순차 진행·종료 | 이전 경매 종료 뒤 다음 경매를 수동 시작하고 활성 경매가 없을 때만 방송 종료 | Not ready |
| 송출 장애 | 이미지 대체, 진행 경매 유지, 신규 경매 차단, 조건 충족 후 5분 미복구 시 자동 종료 | Not ready |
| Kafka 재처리 | 중복·재시도에도 상태와 후속 작업이 한 번만 반영 | Not ready |
| AI 심사 연계 | 승인 전 배치 차단, 승인 후 일반/Live 배치 가능 | Not ready |

## 비기능 검증

- 경매 종료와 입찰이 경합해도 종료 후 입찰이 반영되지 않는다.
- Live 피드 스크롤·재연결 후 현재 상품과 최고가가 서버 상태와 일치한다.
- 로그와 이벤트에 토큰, 결제 비밀값과 불필요한 개인정보가 남지 않는다.
- 장애 시 데이터 원본, 복구 순서와 운영자가 확인할 신호를 검증한다.

성능 목표, 동시 시청자·입찰자 수, 지연 시간과 가용성 기준은 미정이며 확정 후 부하·내구 테스트 합격선을 추가한다.

## 배포 및 시연 진입 조건

- 각 컴포넌트의 필수 테스트와 계약 테스트가 통과한다.
- 위 시나리오 중 시연 범위가 통과하고 결과가 실행 계획에 기록된다.
- 사용할 submodule 커밋이 확정되어 있다.
- 환경변수와 비밀값이 저장소 밖에서 준비되어 있다.
- 알려진 실패 항목과 시연 영향, 대체 흐름이 기록되어 있다.

## 결과 기록

테스트 실행 일시, 대상 커밋, 환경, 데이터 fixture, 결과와 알려진 문제를 해당 실행 계획 또는 시연 기록에 남긴다.
