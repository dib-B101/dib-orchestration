# 앱 탐색·배송지·경매 가격 표시 개선

## 범위와 완료 조건

- 저장 배송지에 도로명주소와 상세주소, 받는 사람, 연락처를 각각 저장하고 조회한다.
- 기존 배송지를 선택하면 주문 배송지 입력 폼의 모든 해당 값이 채워진다.
- 기존 데이터의 받는 사람과 연락처는 회원 이름·휴대전화로 보완한다.
- 기존에 한 문자열로 저장한 상세주소는 구분 가능한 경우 분리하고, 불명확하면 주소 원문을 보존한다.
- 배송지 추가·수정 화면에서 새 수령 정보를 입력·수정할 수 있다.
- 홈 카테고리 탐색에서 서버의 전체 목록을 표시하고 실패 시 재조회할 수 있다.
- Live 경매와 일반 경매 상세의 긴 가격을 줄바꿈 없이 영역에 맞춰 축소한다.

## 영향 컴포넌트

- Backend: address 스키마, API, 조회 및 변경 로직
- Frontend: 배송지 모델·관리·주문 입력, 카테고리 탐색, 경매 가격 표시
- Orchestration: 제품 인수 조건

## 결정

- 사용자 확인: 배송지별로 받는 사람과 연락처를 저장하며, 기존 배송지는 회원정보를 기본값으로 사용한다.
- 기존 앱 요청과 데이터의 호환성을 위해 새 API 필드는 선택 입력으로 추가한다.
- 홈 카테고리 8개 임시 목록은 실제 서버 ID와 일치하지 않으므로 제거한다. 화면 진입 시 서버 목록을 재조회하고 실패 메시지와 재시도를 제공한다.
- 두 경매 화면은 같은 가격 표시 컴포넌트를 사용해 글자 폭을 측정하고 입찰 바운스 여백까지 반영한다.
- 입찰 이력이 없는 사용자는 마감 임박 시에도 가격 바운스를 적용하지 않고, 다른 사용자의 입찰은 숫자 변화로만 표시한다.

## 검증 결과 및 남은 작업

- 배송지 변환 단위 테스트와 백엔드 address 명령·조회 테스트 통과.
- Android `:app:assembleDebug` 통과. 개발용 에뮬레이터에서 홈 카테고리 19개 표시 확인.
- 로컬 API는 19개 카테고리를 반환했으나 기존 에뮬레이터 화면은 8개 임시 목록을 표시했다. 수정 후 서버 응답 19개를 표시한다.
- 새 address 컬럼을 사용하는 실제 주문 저장 흐름은 백엔드 마이그레이션 적용 이후 함께 확인해야 한다.
