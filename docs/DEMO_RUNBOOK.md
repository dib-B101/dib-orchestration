# Demo Runbook

일반 경매와 세로형 Live 경매가 하나의 경매 정책 위에서 동작함을 같은 순서와 조건으로 반복 시연한다.

## 시연 정보

| 항목 | 값 |
| --- | --- |
| 시연 목적 | 일반 경매 탐색·입찰과 Live 방송·순차 상품 경매 및 익명 권한을 검증한다. |
| 예상 시간 | TBD |
| 시연 환경 | TBD |
| 진행자 | TBD |

## 준비 데이터

- 익명 브라우저 세션 1개
- 판매자 계정 1개, 입찰 회원 계정 2개
- AI 승인 상품: 일반 경매용 1개 이상, Live용 2개 이상
- 곧 시작하거나 진행 중인 일반 경매와 마감 30초 이내 검증용 경매
- 최대 10개 제한을 확인할 수 있는 Live 설정, 커버와 상품 이미지
- 송출 가능한 환경 또는 장애 fallback을 재현할 검증 수단

## 사전 점검

- [`docs/DEPLOYMENT.md`](DEPLOYMENT.md)에 따라 대상 환경과 의존성을 확인한다.
- [`docs/TEST_STRATEGY.md`](TEST_STRATEGY.md)의 시연 범위 테스트를 완료한다.
- 계정, 예치금 조건, 샘플 상품의 AI 승인 상태를 확인한다.
- 예약 경매 시각과 Live 송출 세션이 시연 시간에 맞는지 확인한다.
- 실패 시 사용할 검증 로그, 스크린샷 또는 사전 녹화 자료를 준비한다.

| 3 | 회원 로그인 후 일반 경매 입찰 | 공통 예치금·입찰 정책 | 유효 입찰 반영, 최고가 실시간 갱신 | TBD |

| 8 | 회원이 Live 경매에 입찰 | 일반/Live 공통 경매 코어 | 최고가와 종료 상태 동기화 | TBD |
| 9 | 활성 경매 중 방송 종료 후 경매 종료 뒤 재시도 | 종료 조건 | 첫 요청 거절, 경매 종료 후 방송 종료 성공 | TBD |
| 10 | 가능하면 송출 장애 재현 | 이미지 fallback과 거래 연속성 | 이미지 표시, 진행 경매 유지, 신규 경매 차단 | TBD |

## 실패 대응

| 실패 상황 | 즉시 확인 | 대체 시나리오 |
| --- | --- | --- |
| 서비스 접근 실패 | 배포 상태, 주소, submodule 조합 | 마지막 검증 환경 또는 녹화 자료 사용 |
| 일반 경매 예약 시각 불일치 | 서버 시각, 스케줄 키·버전 | 사전 준비한 진행/마감 임박 fixture로 설명 |
| WebSocket 갱신 실패 | 연결·구독·인증과 서버 스냅샷 | REST snapshot과 이벤트 로그로 최종 상태 확인 |
| Live 송출 실패 | 공급자 세션, webhook, 네트워크 | 상품 이미지 fallback 흐름과 서버 경매 상태 시연 |
| AI 응답 지연·실패 | AI health와 심사 상태 | 사전 승인 fixture로 핵심 경매 흐름 계속 |
