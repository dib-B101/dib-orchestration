# System Overview

상태: Draft

## 문제 정의

기존 정적 이미지 중심의 숏폼 상품 노출만으로는 판매자와 구매자가 실시간으로 상품을 설명하고 경쟁 입찰에 참여하는 경험을 제공하기 어렵다. 동시에 모든 경매를 영상 기반으로 강제하면 일반적인 상품 탐색과 예약 경매 사용성이 떨어진다.

DIB는 하나의 경매 코어를 기반으로 쇼핑몰형 일반 경매와 세로형 실시간 Live 경매를 함께 제공한다.

## 제품 목표

- 승인된 상품을 일반 경매 또는 Live 경매로 판매할 수 있게 한다.
- 일반 경매는 익숙한 쇼핑몰형 탐색과 예약 자동 시작을 제공한다.
- Live 경매는 방송 중인 판매자를 세로형 피드로 탐색하고 실시간 입찰할 수 있게 한다.
- 두 경매 유형의 입찰·보증금·연장·낙찰·거래 규칙을 공통화한다.
- 상품 중복 노출과 동시 낙찰을 시스템적으로 방지한다.

## 대상 사용자

| 사용자 | 주요 목표 |
| --- | --- |
| 비회원 | 일반 경매 공개 정보와 Live 방송·현재 경매 상태를 조회한다. |
| 회원·구매자 | 상품을 찜하고 보증금을 결제한 뒤 일반 또는 Live 경매에 입찰한다. |
| 회원·판매자 | 상품을 등록·검수받고 일반 경매를 예약하거나 Live를 구성·진행한다. |
| 관리자 | 상품 검수·판매중지, 신고, 이상 입찰과 거래 분쟁을 관리한다. |
| 시스템 | 예약 시작·종료, 입찰 순서, 실시간 상태, 환불·알림과 장애 복구를 처리한다. |

## 핵심 사용자 흐름

1. 판매자가 상품을 등록하고 AI 검수를 통과한다.
2. 판매자는 상품을 일반 경매로 예약하거나 Live에 편성한다.
3. 사용자는 쇼핑몰형 일반 경매 화면 또는 세로형 Live 피드에서 판매 대상을 찾는다.
4. 로그인 회원이 경매별 보증금을 결제하고 입찰한다.
5. 시스템이 마감 연장과 종료를 처리하고 낙찰 또는 유찰을 확정한다.
6. 낙찰 시 주문·결제·배송·거래확정·정산 흐름으로 이어진다.

세부 제품 규칙은 [`auction-platform.md`](auction-platform.md)를 따른다.

## 시스템 범위

### 포함

- 일반 경매 홈·목록·검색·상세와 예약 자동 시작
- 세로형 방송 중 Live 피드와 판매자의 상품별 수동 경매 시작
- 공통 입찰·보증금·연장·낙찰·거래
- 상품 등록·AI 검수와 불법 상품 탐지
- Live 채팅·신고·시청자 집계와 송출 장애 복구
- 낙찰 후 결제·배송·거래확정·정산
- 이상 입찰 분석과 관리자 검토

### 제외

- 예약 방송, 방송 대기실과 Live 다시보기
- 판매자 팔로우·구독
- 블라인드 경매, 입찰 상한과 즉시구매
- 진행 중 경매의 판매자 강제 취소
- 추천·인기 점수의 확정 산식

## 제약사항

- 상세 명세 원본은 [B101 명세서 Google Sheet](https://docs.google.com/spreadsheets/d/1qjqjh2OFjFtgLKkJVJVqcNBo5vOF85LSEs8z4MNtQAg/edit)다.
- 공통 Auction 모델은 일반·Live 유형을 구분하면서 동일한 입찰 계약을 사용해야 한다.
- 한 상품은 일반 경매와 Live 경매에 동시에 노출할 수 없다.
- Live는 방송당 최대 10개 상품과 동시 진행 경매 1개로 제한한다.
- 스트리밍 공급자와 추천·인기 점수 산식은 아직 확정되지 않았다.
- 제공된 ERD는 초안이며 목표 모델과의 차이를 설계 문서에서 추적한다.
