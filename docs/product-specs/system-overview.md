# 시스템 개요

> Status: Active

## 문제 정의

DIB는 일반 경매와 Live 방송 경매를 한 거래 흐름 안에서 제공하는 중고 거래 서비스다. 거래량이 늘면 운영자가 문의, 금지 상품, 이상 입찰, 신고와 계정 제재를 여러 데이터 원본에서 수동으로 확인해야 하므로 사용자 거래 흐름과 운영 흐름을 함께 자동화해야 한다.

## 제품 목표

- Android 앱에서 상품 탐색과 등록부터 일반·Live 경매, 낙찰, 결제, 배송과 정산까지 연결된 거래 경험을 제공한다.
- 상품 검수, 이상 입찰 탐지와 추천에 AI를 활용하되 불확실한 판정은 관리자 검토로 연결한다.
- 운영자가 하나의 웹 콘솔에서 문의와 위험 신호를 확인하고 필요한 조치를 완료할 수 있게 한다.
- 실시간 상호작용과 안정적인 거래 처리를 지원한다.

## 대상 사용자

| 사용자 | 역할 |
| --- | --- |
| 비회원 | 공개된 상품, 경매와 Live를 탐색한다. |
| 회원 | 구매자 또는 판매자로 상품, 경매와 거래 기능을 사용한다. |
| 관리자 | 회원, 상품 검수, 문의, 신고와 거래 운영 업무를 처리한다. |

## 핵심 사용자 흐름

1. 회원이 Android 앱에서 상품을 등록한다.
2. 백엔드가 AI 검수 서버에 상품명·설명·이미지를 보내고 자동 승인, 자동 반려 또는 관리자 검토 대기로 분류한다.
3. 승인된 상품은 일반 경매 또는 Live 방송 경매를 거쳐 주문, 결제, 배송과 정산으로 이어진다.
4. 관리자는 웹 콘솔에서 보류 상품과 판정 근거를 확인하고 최종 승인 또는 반려한다.
5. 관리자는 같은 콘솔에서 고객 문의에 답변하고 이상 입찰과 신고를 조사해 필요한 운영 조치를 수행한다.

## 시스템 범위

### 포함

- Android 사용자 앱과 React 관리자 웹
- 회원 인증과 관리자 역할 기반 접근 제어
- 상품 등록·탐색·검수, 일반·Live 경매와 실시간 입찰
- 주문, 결제, 배송, 거래 확정과 정산
- 채팅, 알림, 문의, 신고와 회원 제재
- 백엔드를 경계로 한 AI 검수·추천·이상 입찰 연동

### 상세 명세 관리

요구사항, 기능, API와 ERD는 개발 중 변경되는 작업 자료이므로 이 저장소에 복제하지 않는다. 관련 작업을 수행할 때 사용자가 제공한 최신 Sheet와 ERD를 해당 작업의 기준으로 사용한다.

확정된 시스템 수준 결정만 `ARCHITECTURE.md`와 관련 실행 계획에 기록하고, 컴포넌트 내부 구현과 실행 가능한 스키마는 해당 submodule이 소유한다.

### 제외

- 관리자 웹에서 AI 서버나 데이터베이스를 직접 호출하는 구조
- 관리자 역할 외 사용자의 운영 기능 접근
- AI 판정만으로 관리자 확인 없이 애매한 상품을 영구 차단하는 정책
- 운영 배포와 외부 모델 키 발급

## 성공 지표

- 상품 탐색부터 거래 완료까지 사용자 흐름이 컴포넌트 간에 단절되지 않는다.
- 관리자가 각 운영 큐를 별도 데이터베이스 조회 없이 처리할 수 있다.
- 검수 서버 장애나 2차 모델 미설정 시 상품이 소실되지 않고 `PENDING` 큐에 남는다.
- 명백한 거래 제한 품목은 규칙 단계에서 자동 반려된다.
- 정량 목표는 제품 의사결정 후 확정한다.

## 제약사항

- 브라우저는 백엔드의 `/api/v1/admin/**` API만 호출하며 AI 서버와 데이터베이스에 직접 접근하지 않는다.
- 2차 멀티모달 AI는 Anthropic, OpenAI 또는 SSAFY GMS 키가 있어야 활성화된다. 키가 없으면 금칙어 규칙은 동작하고 나머지는 관리자 검토 대기로 보낸다.
- 로컬 통합 환경의 관리자 웹은 기본 `http://localhost:3000`, 백엔드는 `http://localhost:8080`을 사용한다.
